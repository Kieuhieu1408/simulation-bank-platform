# Corebank V3: Roadmap Kiến Trúc Nhất Quán & Clean Architecture

## 1. Vấn đề của V2
Phiên bản V2 đã đánh dấu bước tiến lớn khi áp dụng Event Sourcing cho Transfer và Account. Tuy nhiên, V2 đang mang tính chất "chữa cháy" (tactical fixes) cho các vấn đề concurrency (Deadlock, Pessimistic lock) hơn là áp dụng một kiến trúc nhất quán (Strategic design).
*   Một hệ thống bị lai tạp: Nửa Event Sourcing, nửa CRUD bằng JPA.
*   Application Layer (Command Handlers) đang chứa đầy Infrastructure logic (JDBC queries, DB retries).
*   Thiếu vắng Ports & Adapters.

## 2. Tầm nhìn V3
V3 sẽ là phiên bản "làm sạch" toàn bộ hệ thống, hướng tới một chuẩn mực Clean Architecture duy nhất cho tất cả các module.

### Mục tiêu chính:
1.  **Strict Clean Architecture:** Áp dụng triệt để Dependency Rule.
2.  **Thống nhất kiến trúc:** Áp dụng Ports & Adapters xuyên suốt.
3.  **Tách rạch ròi Data Model và Domain Entity:** Loại bỏ hoàn toàn JPA annotation khỏi Domain.

## 3. Lộ trình thực hiện (Roadmap)

### Phase 1: Chuẩn hóa Domain Layer (Entities & Aggregates)
*   Review lại toàn bộ package `domain`.
*   Chuyển đổi `Customer`, `BankCard` thành Pure Java Class.
*   Đẩy các class JPA Entity (chứa `@Entity`, `@Table`) xuống package `infrastructure.persistence.entity`.
*   Thêm mapper để chuyển đổi giữa Domain Entity và JPA Entity.

### Phase 2: Chuẩn hóa Application Layer (Ports & Use Cases)
*   Tạo các giao diện (Ports) trong application layer: `AccountRepositoryPort`, `CustomerRepositoryPort`, `IdGeneratorPort`.
*   Refactor các Command/Query Handlers: Xóa bỏ việc gọi trực tiếp `JdbcClient`, `JpaRepository`. Thay vào đó, inject các Ports.
*   Xóa bỏ việc xử lý Spring Exception (`DataIntegrityViolationException`) trong `TransferCommandHandler`. Đẩy logic retry này ra một tầng bao bọc (Gateway) hoặc xử lý chung ở AOP/Interceptor.

### Phase 3: Hoàn thiện Infrastructure Layer (Adapters)
*   Tạo các Adapter class implement các Ports ở Phase 2.
*   Đưa logic gọi database thuần túy (như lấy sequence Oracle `SELECT ... FROM DUAL`) vào trong các Adapter tương ứng.

### Phase 4: Đồng bộ kiến trúc CQRS
*   Đảm bảo toàn bộ thao tác Write (Command) đều tương tác qua Domain Aggregates và được lưu qua Ports.
*   Toàn bộ thao tác Read (Query) sẽ đọc trực tiếp từ các Read Models (Views/Projections) thông qua Query Handlers, tối ưu hóa triệt để cho tốc độ.

## Kết luận
Corebank V3 không phải là việc đẻ thêm tính năng mới, mà là quá trình trả nợ kỹ thuật (Technical Debt) từ V1/V2, mang lại một kiến trúc bền vững, dễ dàng bảo trì và mở rộng trong tương lai 5-10 năm tới.
